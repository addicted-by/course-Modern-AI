D02 · PCA: карта для исследования данных¶

Связь со слайдом 2. Строка таблицы становится точкой с координатами PC1 и PC2. По карте выбираем объекты, возвращаемся к их изображениям и проверяем, действительно ли соседи похожи.

Используем те же изображения, ID и train/test, что в D01. Этот ноутбук независим: никаких файлов, заранее сохранённых D01, не требуется. Здесь нет классификатора или алгоритма кластеризации. Известные метки цифр можно наложить только после построения проекции для проверки интерпретации.

За 5–10 минут: PCA 2D → строка и точка → соседи в 2D и 64D → восстановление и потерянные различия → необязательная раскраска известными метками.

Запуск. Выберите Python-ядро и выполните Restart Kernel → Run All. При необходимости установите зависимости в терминале:

python -m pip install numpy scipy pandas matplotlib scikit-learn threadpoolctl ipykernel

Данные встроены в scikit-learn; после установки сеть не нужна. Рабочий каталог — папка ноутбука; все результаты сохраняются только в outputs/d02/.

1. Те же объекты, то же разбиение¶

Одна цифра — изображение 8×8 — строка из 64 признаков. Число строк после PCA не меняется. Для связи с D01 воспроизводим разбиение, но в исследовательские графики включаем только train. Test оставляем в стороне.

ID сохраняет личность объекта; номер строки после train_test_split может измениться. Поэтому мы не называем «нулевой строкой» одно и то же изображение до и после разбиения.

2. Две координаты вместо 64¶

PCA выбирает направления с наибольшей дисперсией. После стандартизации и центрирования $A=U\Sigma V^\top$, а координаты карты — $Z=A V_{[:,1:2]}$. Для каждого объекта это ровно два числа.

Оси — линейные комбинации пикселей, а не номера классов. Метки не передаём ни scaler, ни PCA. Масштабирование — явное решение, согласованное с D01; оно делает вклад редких и часто меняющихся пикселей сопоставимым.

4. Близко на карте — обязательно близко в исходном пространстве?¶

Сравним ближайших соседей выбранного объекта по евклидову расстоянию в стандартизованных 64D и в PCA 2D. Это две разные геометрии. Проекция может свести рядом объекты, различающиеся по отброшенным компонентам.

Ортогональная проекция не увеличивает расстояния: $\|z_i-z_j\|\leq\|x_{s,i}-x_{s,j}\|$. Но порядок соседей может измениться. Наше измерение 64D использует масштабированные признаки; оно не претендует на идеальную метрику визуального сходства.

5. Что потеряно в двух измерениях¶

Оценим три разные стороны потери информации: долю дисперсии, совпадение списков соседей и ранговую корреляцию попарных расстояний. Это характеристики проекции, не метрики качества кластеризации.

Для скорости корреляцию считаем на фиксированной случайной подвыборке до 300 train-объектов. Восстановление $\widehat X_s=ZV_2^\top+\mu$ показывает, что двух чисел недостаточно, чтобы вернуть исходные изображения.

assert np.all(d2 <= d64 + 1e-10)
distance_rank_correlation = float(spearmanr(d64, d2).statistic)

# Наборы соседей для той же подвыборки: исключаем точный индекс запроса.
def neighbor_sets(data, query_positions, count):
    raw = NearestNeighbors(n_neighbors=count + 1).fit(data).kneighbors(
        data[query_positions], return_distance=False
    )
    return [set(row[row != pos][:count]) for pos, row in zip(query_positions, raw)]

sets_64d = neighbor_sets(X_train_scaled, probe_pos, N_NEIGHBORS)
sets_2d = neighbor_sets(Z, probe_pos, N_NEIGHBORS)
mean_neighbor_recall = float(np.mean([len(a & b) / N_NEIGHBORS for a, b in zip(sets_64d, sets_2d)]))
metrics = {"сохранённая дисперсия": explained_fraction,
           "относительная квадратичная ошибка восстановления": float(relative_error_sq),
           "средняя доля сохранённых соседей": mean_neighbor_recall,
           "Spearman корреляция расстояний": distance_rank_correlation}
display(pd.Series(metrics).to_frame("значение").round(4))

6. Необязательная проверка известными метками¶

Только теперь окрашиваем уже вычисленные координаты по известной цифре. Цвет не участвовал в построении PCA и не присваивает кластер: это внешняя подсказка для исследования. Перекрытие классов ожидаемо; большая дисперсия не гарантирует разделение классов. Чтобы оценивать кластеризацию, нужно отдельно задать алгоритм, критерии и протокол проверки.

SHOW_LABEL_AUDIT=False скрывает этот шаг. Меняя его, мы не меняем Z.

Вопросы для исследования¶

  1. Выберите другой SELECTED_ID из train-таблицы и повторите запуск. Совпадают ли списки соседей в 2D и 64D? Проверяйте изображения, а не только расстояния.
  2. Какая доля вариации отсутствует на карте? Почему два похожих положения на карте не гарантируют одинаковые цифры?
  3. Сравните StandardScaler с одним центрированием, заменив его на StandardScaler(with_std=False). Как изменится геометрия карты? Это смена метрики признаков, а не «ошибка PCA».
  4. Попробуйте три компоненты и сравните сохранение соседей. Новые оси могут вернуть различия, которых нет в 2D.

Вывод для слайда: карта помогает выбрать объекты для исследования. Сама карта ещё не доказывает существование классов, кластеров или аномалий.
