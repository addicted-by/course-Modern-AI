1. Восстанавливаем смысл таблицы со слайда¶

На слайде единица — факт наблюдения, а пустая ячейка — отсутствие наблюдения. Здесь в точности те же шесть связей: u1 → i1, i3, u2 → i2, i4, u3 → i1, i4.

Для численного примера добавим на эти связи учебные явные оценки от 1 до 5. Слева — исходная маска взаимодействий, справа — придуманные рейтинги. Рейтинг отсутствует — храним NaN, а не измеренный ноль. Это explicit-feedback ALS: в ошибку входят только наблюдённые оценки. Позже отдельно обсудим отличие от implicit feedback.

2. Одно обновление: зафиксировать объекты и решить ridge-задачу¶

Для факторов пользователей $P\in\mathbb R^{n_u\times k}$ и объектов $Q\in\mathbb R^{n_i\times k}$ оптимизируем

$$J(P,Q)=\sum_{(u,i)\in\Omega}(r_{ui}-p_u^\top q_i)^2+ \lambda\left(\|P\|_F^2+\|Q\|_F^2\right),\qquad \lambda>0.$$

Когда $Q$ зафиксирована, строка $p_u$ зависит только от рейтингов пользователя $u$. Пусть $B=Q_{\Omega_u}$ — строки факторов наблюдённых объектов. Тогда

$$A_u p_u=b_u,\qquad A_u=B^\top B+\lambda I_k,\qquad b_u=B^\top r_u.$$

$z^\top A_u z=\|Bz\|^2+\lambda\|z\|^2>0$ для ненулевого $z$, поэтому матрица положительно определена. Разложим малую матрицу $A_u=LL^\top$ и выполним два треугольных решения. Обратная матрица не нужна; размер системы — число факторов $k$, а не число всех взаимодействий.

scipy.linalg.cho_factor строит факторизацию, cho_solve использует её для решения.

def ridge_update(B, ratings, lam):
    """Одно точное регуляризованное обновление, включая отсутствие наблюдений."""
    B = np.asarray(B, dtype=np.float64)
    ratings = np.asarray(ratings, dtype=np.float64)
    if not np.isfinite(lam) or lam <= 0:
        raise ValueError("lambda должна быть конечной и строго положительной")
    if B.ndim != 2 or ratings.shape != (B.shape[0],):
        raise ValueError("Ожидаются B: (n_observed, k), ratings: (n_observed,)")
    if B.shape[1] == 0 or not np.isfinite(B).all() or not np.isfinite(ratings).all():
        raise ValueError("Нужны конечные значения и хотя бы один фактор")
    A = B.T @ B + lam * np.eye(B.shape[1])
    b = B.T @ ratings
    factor = cho_factor(A, lower=True)
    solution = cho_solve(factor, b)
    # Берём только нижний треугольник: второй треугольник не является частью L.
    L = np.tril(factor[0])
    return solution, A, b, L


def objective_parts(R, P, Q, lam):
    observed = np.isfinite(R)
    residual = R[observed] - (P @ Q.T)[observed]
    squared_error = float(residual @ residual)
    regularizer = float(lam * (np.sum(P ** 2) + np.sum(Q ** 2)))
    return squared_error, regularizer


def objective(R, P, Q, lam):
    return sum(objective_parts(R, P, Q, lam))

Та же локальная задача через QR¶

Регуляризацию можно включить дополнительными строками:

$$\min_p\left\|\begin{bmatrix}B\\ \sqrt\lambda I\end{bmatrix}p- \begin{bmatrix}r\\0\end{bmatrix}\right\|^2.$$

QR и Холецкий решают здесь одну задачу; на этом хорошо обусловленном примере результаты совпадут с точностью округления. QR работает с расширенной матрицей напрямую. Формирование $B^\top B$ может ухудшить обусловленность; это одна из причин, почему Холецкий не является обязательным определением ALS.

3. От маленькой схемы к прогнозированию рейтингов курсов¶

У 60 вымышленных студентов есть скрытые предпочтения по трём направлениям, у 40 вымышленных курсов — три признака. Генератор создаёт непрерывный рейтинг $r_{ui}=3+0.65\,p_u^\top q_i+\varepsilon_{ui}$, где $\varepsilon\sim\mathcal N(0,0.04^2)$. Это искусственный пример, согласованный с низкоранговой моделью; факторам нельзя приписывать смысл без дополнительного анализа.

Для каждого студента случайно выбираем 20 train-оценок и 6 test-оценок. Остальные пары вообще не наблюдались. Разбиение фиксируется один раз. Среднее, факторы и baseline оцениваются только по train. Test используется один раз в финальном сравнении; ранг, регуляризация и число эпох уже заданы выше.

def make_synthetic_split(seed, n_users=60, n_items=40, latent_rank=3):
    rng = np.random.default_rng(seed)
    hidden_users = rng.uniform(-1, 1, (n_users, latent_rank))
    hidden_items = rng.uniform(-1, 1, (n_items, latent_rank))
    complete_scores = 3.0 + 0.65 * hidden_users @ hidden_items.T
    complete_scores += rng.normal(0, 0.04, complete_scores.shape)
    train = np.full((n_users, n_items), np.nan)
    test_u, test_i = [], []
    for u in range(n_users):
        shuffled = rng.permutation(n_items)
        train_items, test_items = shuffled[:20], shuffled[20:26]
        train[u, train_items] = complete_scores[u, train_items]
        test_u.extend([u] * len(test_items))
        test_i.extend(test_items)
    test_u, test_i = np.array(test_u), np.array(test_i)
    test_y = complete_scores[test_u, test_i].copy()
    # Не возвращаем скрытые факторы или заполненную таблицу обучающему коду.
    return train, test_u, test_i, test_y

4. Полный ALS: пользователи → объекты → повторить¶

В большой модели используем $\hat r_{ui}=\mu_{train}+p_u^\top q_i$. Среднее $\mu_{train}$ вычисляется заранее и фиксируется, поэтому ALS обучается на центрированных оценках. Регуляризация остаётся $\lambda(\|P\|_F^2+\|Q\|_F^2)$ — без умножения на число оценок пользователя или объекта.

В пользовательской фазе все строки $P$ обновляются при фиксированной $Q$; в следующей фазе все строки $Q$ — при фиксированной новой $P$. После каждой фазы проверяем, что полная цель $J$ не выросла. Убывание train-цели не гарантирует убывания test-ошибки или достижения глобального минимума совместной задачи.

def fit_als(centered_R, rank, lam, n_epochs, seed):
    observed = np.isfinite(centered_R)
    if not observed.any():
        raise ValueError("Нужно хотя бы одно train-наблюдение")
    if rank < 1 or n_epochs < 1 or not np.isfinite(lam) or lam <= 0:
        raise ValueError("Требуются rank >= 1, n_epochs >= 1, lambda > 0")
    rng = np.random.default_rng(seed)
    P = rng.normal(0, 0.2, (centered_R.shape[0], rank))
    Q = rng.normal(0, 0.2, (centered_R.shape[1], rank))
    users_to_items = [np.flatnonzero(row) for row in observed]
    items_to_users = [np.flatnonzero(col) for col in observed.T]
    history = []

    def record(epoch, phase):
        squared_error, penalty = objective_parts(centered_R, P, Q, lam)
        total = squared_error + penalty
        if history:
            previous = history[-1]["objective"]
            assert total <= previous + 1e-9 * max(1.0, previous), (phase, previous, total)
        history.append({"epoch": epoch, "phase": phase, "objective": total,
                        "squared_error": squared_error, "regularizer": penalty,
                        "train_rmse": np.sqrt(squared_error / observed.sum())})

    record(0, "initial")
    for epoch in range(1, n_epochs + 1):
        for u, items in enumerate(users_to_items):
            P[u], _, _, _ = ridge_update(Q[items], centered_R[u, items], lam)
        record(epoch, "users")
        for i, users in enumerate(items_to_users):
            Q[i], _, _, _ = ridge_update(P[users], centered_R[users, i], lam)
        record(epoch, "items")
    return P, Q, pd.DataFrame(history)

5. Проверка на test: с чем сравниваем¶

Две простые отправные точки: одно train-среднее и аддитивный baseline $\mu_{train}+b_u+b_i$. Во втором случае смещения обучаются только по train с фиксированной регуляризацией 5.0. У ALS и baseline одинаковое разбиение, ни один метод не видел test-рейтинги. Все прогнозы остаются сырыми, без скрытого округления или обрезания к шкале.

RMSE проверяет численные рейтинги на известных отложенных парах. Эта величина не является метрикой качества списка рекомендаций и не подтверждает полезность реальному пользователю.

def fit_bias_baseline(train, mean, lam=5.0, iterations=30):
    observed = np.isfinite(train)
    user_bias = np.zeros(train.shape[0])
    item_bias = np.zeros(train.shape[1])
    for _ in range(iterations):
        for u in range(train.shape[0]):
            items = np.flatnonzero(observed[u])
            user_bias[u] = np.sum(train[u, items] - mean - item_bias[items]) / (len(items) + lam)
        for i in range(train.shape[1]):
            users = np.flatnonzero(observed[:, i])
            item_bias[i] = np.sum(train[users, i] - mean - user_bias[users]) / (len(users) + lam)
    return mean + user_bias[:, None] + item_bias[None, :]


def rmse(actual, predicted):
    return float(np.sqrt(np.mean((actual - predicted) ** 2)))

7. Что связывает демо со слайдом D24¶

  • Фиксированная сторона факторизации превращает обновление в небольшую задачу наименьших квадратов с регуляризацией. Затем стороны меняются ролями.
  • При $\lambda>0$ локальная матрица SPD; её разложение Холецкого решает систему. В демо не факторизуется вся таблица рейтингов и не вычисляется обратная матрица.
  • Мы проверили уменьшение полной train-цели после каждой фазы. Качество за пределами train проверяется отдельно.
  • Пропуски исключены из explicit-feedback ошибки. Заменять их измеренными нулями означало бы изменить задачу.

Отличие от ссылки implicit на слайде. В библиотеке implicit.cpu.als.AlternatingLeastSquares используется модель implicit feedback: ненаблюдённым событиям назначают предпочтение и confidence согласно её функции потерь. Это не утверждение, что в исходных данных измерен рейтинг 0. В опубликованном CPU API use_cg=True по умолчанию; ALS может использовать CG вместо прямого решения через Холецкого. Наша реализация решает другую, явно записанную explicit-feedback цель.

Вопросы для занятия: зачем здесь $\lambda I$; почему неизвестный пользователь получает средний прогноз; почему убывание train-цели не обещает лучшего test; чем отличаются матрица наблюдений и заполненная матрица прогнозов? Чтобы экспериментировать с $k$ и $\lambda$ честно, добавьте отдельную validation-часть и оставьте test для финального отчёта.

Первичные источники: SciPy: cho_factor, SciPy: cho_solve, документация implicit ALS. Ссылки проверены 2026-10-07.
