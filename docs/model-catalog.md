# База моделей и сборка Model Showcase

`data/models.sqlite3` — основное хранилище каталога. В нём задаются семейства,
модели, порядок, адреса страниц, презентации и точные привязки к слайдам.
Отдельного JSON-реестра нет.

```text
SQLite: модели, семейства, презентации, привязки
                        ↓
             чтение исходников презентаций
                        ↓
       обновление импортированного содержимого в SQLite
                        ↓
             единые шаблоны страниц Model Showcase
                        ↓
                    Quarto HTML
```

## Какие данные редактируются

Основные записи хранятся в таблицах:

- `families`: ID, название и порядок семейства;
- `presentations`: ID, путь к QMD, адрес HTML, название и модуль;
- `models`: ID модели, URL страницы, категория, семейство и порядок;
- `model_sources`: точная презентация, ID слайда, роль `card` / `results`
  и порядок источников каждой модели;
- `comparisons`: определения сравнений и их исходные слайды.

Синхронизация сохраняет эти записи. Она обновляет импортированные таблицы
`slides`, `model_content`, `model_disclosures` и хеши источников. Название модели,
характеристики, результаты и заметки извлекаются из явно связанных слайдов.
Оглавление презентации не управляет каталогом.

Одна модель может использовать несколько карточек и слайдов результатов из
разных презентаций. Первый слайд каждой роли задаёт основные поля и превью;
все указанные слайды и заметки выводятся на странице.

## Обычное обновление

1. Изменить QMD презентации или её include-файл в проекте.
2. Запустить `quarto render` из корня проекта.

Pre-render сначала синхронизирует содержимое БД, затем строит страницы только
из SQLite. После рендера проверяются ID и номера слайдов в готовых презентациях.

Привязка использует постоянный ID, например `sc-llm-gpt6-astra`. При перестановке
слайдов обновляется номер, а связь с моделью сохраняется. Если исходник исчез
или стал некорректным, синхронизация завершается ошибкой, изменения содержимого
откатываются и сборка сайта останавливается.

## Редактирование каталога

Базу можно открыть в SQLite-редакторе или командой:

```sh
sqlite3 data/models.sqlite3
```

В каждой редактирующей сессии включайте внешние ключи:

```sql
PRAGMA foreign_keys = ON;
```

Например, изменить отображаемое название семейства:

```sql
UPDATE families SET label = 'GPT family' WHERE id = 'gpt';
```

Изменить семейство модели:

```sql
UPDATE models SET family_id = 'gpt' WHERE id = 'sc-llm-gpt6-astra';
```

Добавление новой модели выполняется одной транзакцией. Замените примерные
ID на существующее семейство, зарегистрированную презентацию и реальные слайды:

```sql
BEGIN;
INSERT INTO models (id, slug, category, family_id, sort_order)
SELECT 'example-model', 'example-model', 'llm', 'gpt',
       COALESCE(MAX(sort_order), -1) + 1 FROM models;

INSERT INTO model_sources (model_id, presentation_id, slide_id, role, ordinal)
VALUES ('example-model', 'intro-showcase', 'example-model-card', 'card', 0),
       ('example-model', 'intro-showcase', 'example-model-results', 'results', 1);
COMMIT;
```

Далее выполните `quarto render`. Импорт проверит привязки и заполнит содержимое.
Новая презентация регистрируется в таблице `presentations`; её также нужно
включить в `lectures.yml`, чтобы сайт собирал соответствующий HTML.

## Команды

```sh
# Полная сборка с автоматической синхронизацией:
quarto render

# Только обновить содержимое БД из презентаций:
python3 scripts/sync-models.py

# Синхронизация и подготовка QMD страниц:
python3 scripts/build-showcase.py

# Подготовка QMD только из текущей БД:
python3 scripts/build-showcase.py --no-sync

# Проверки:
python3 -m unittest discover -s tests -v
python3 scripts/check-model-publication.py
```

Просмотр точных источников модели:

```sql
SELECT m.id, ms.role, p.source_path AS presentation,
       s.slide_id, s.position, s.source_path AS slide_source
FROM models m
JOIN model_sources ms ON ms.model_id = m.id
JOIN slides s ON s.presentation_id = ms.presentation_id AND s.slide_id = ms.slide_id
JOIN presentations p ON p.id = s.presentation_id
WHERE m.id = 'sc-llm-gpt6-astra'
ORDER BY ms.ordinal;
```

## Хранение и миграции

Файл `data/models.sqlite3` является данными проекта и должен храниться в Git
вместе с исходниками презентаций. Это не удаляемый кэш. При отсутствии файла
сборка сообщает об ошибке; каталог автоматически не создаётся заново.
Журналы SQLite исключены из Git.

Схема находится в `scripts/model_catalog_schema.sql`. Переход со схемы 1 на 2
сохраняет записи непосредственно из существующей SQLite-базы; JSON для миграции
не требуется. Обычная синхронизация выполняется транзакцией в существующей БД,
не пересоздаёт каталог и сохраняет внесённые в него изменения.

Для совершенно нового проекта пустую БД можно создать явно через
`create_catalog(path)` из `scripts/model_catalog.py`. Этот вызов отказывается
перезаписывать существующий файл. Он не нужен для сборки этого проекта.

## Поддерживаемые презентации

Адаптер рассчитан на Quarto-слайды курса с явными заголовками
`## … {#stable-id}`, HTML-карточками `bn` / `ds`, результатами `sr` и заметками
`.notes`. Вложенные include-файлы поддерживаются. Обычный видимый Markdown
конвертируется Quarto/Pandoc; вычислительные блоки при импорте не исполняются.

Для другого макета карточки потребуется адаптер извлечения полей. Неизвестные
статусы и неподдерживаемые shortcodes вызывают ошибку. Автоматические титульные
слайды и другие правила нумерации должны учитываться адаптером: проверка
готовой презентации блокирует несовпадающие номера. Ссылки используют ID слайда.
